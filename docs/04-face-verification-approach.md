# Face Verification Approach Specification — AWS Rekognition

This document outlines the technical design for biometric face verification in the **DEN** mobile application using **Amazon Rekognition Face Liveness** and **CompareFaces**.

---

## 1. Overview & User Flow

Face verification is an **optional identity trust step** in the DEN onboarding funnel (Step 8). Users are never blocked from completing account setup if they choose not to verify immediately.

- **Options**: The screen displays two primary buttons: **"VERIFY NOW"** and **"SKIP FOR NOW"**.
- **Completion Navigation**: Selecting either "VERIFY NOW" or "SKIP FOR NOW" completes the onboarding flow (`updateAuth(isAuthenticated: true, isOnboardingComplete: true)`) and navigates the user directly to their **Profile Screen** (`ProfilePageScreen` / `/home`).
- **Post-Onboarding Verification**: Unverified users can initiate or retry face verification at any time from their Profile Settings.

## 2. Amazon Rekognition Face Liveness & Matching Architecture

### A. Client SDK (Flutter / iOS / Android)
- **Package**: `face_liveness_detector` (pub.dev, which bridges to native AWS Amplify Face Liveness SDKs for iOS and Android).
- **Android Configuration**: Requires Java core library desugaring (`isCoreLibraryDesugaringEnabled = true` & `desugar_jdk_libs:2.0.4`) in `android/app/build.gradle.kts`.
- **Client AWS Decoupling**: The Flutter mobile app **NEVER calls AWS APIs directly** nor stores AWS IAM credentials. It only receives a temporary `sessionId` generated by our backend, runs the capture UX, and notifies our backend upon completion.

### B. Server-Side Rekognition Workflow (Dart Backend)
All AWS SDK calls happen server-side from our own backend using secured IAM credentials:

1. **Create Session**: Client calls `POST /api/onboarding/face-liveness/session`. Our backend calls AWS `CreateFaceLivenessSession` and returns `{ "success": true, "sessionId": "<string>" }`.
2. **Client Capture**: Client executes the `face_liveness_detector` UX using the retrieved `sessionId`.
3. **Submit for Audit**: Client calls `POST /api/onboarding/verify-face` with `{ "sessionId": "<string>" }`.
4. **Liveness Validation**: Backend calls `GetFaceLivenessSessionResults(sessionId)` to confirm liveness confidence score ($> 90\%$) and retrieve the reference face image.
5. **Face Comparison**: Backend calls `CompareFaces` matching the reference face image against the user's primary uploaded profile photo (`photos[0]`).
6. **Result Verification**: If similarity score exceeds threshold ($> 85\%$), backend updates user record (`is_verified = true`).
